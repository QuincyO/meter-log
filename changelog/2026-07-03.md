# 2026-07-03 — A performance pass for scale

`623c402` → `b0fcd46`

The spine and the page loads were both getting slower as the Sheet grew. Six changes, all
aimed at the same thing:

- **Sheet reads memoized per request**, with a cross-request cache for the small
  slow-changing roster tabs (`Employees`, `Teams`, `Captains`, `Subs`, `Metrics`). Any code
  that writes one of those tabs has to bust the cache, or a read later in the same request —
  or a roster read for hours — sees stale data. The big hot tabs are deliberately *not*
  cached: they exceed the size limit and are written on every log. `623c402`, `b0fcd46`
- **`avgDispatchTime` moved off the write path** to an hourly trigger, so its
  stops × dispatch matching never holds the write lock during the quitting-time burst.
- **`previewDailyLog` runs outside the write lock** — it is the one POST that writes nothing,
  so end-of-day prefetch traffic no longer queues behind the crew's real writes. `d7e765a`
- **Optional from/to date windows** on the five viewer reads, instead of always reading
  everything. `bd57c85`
- **Leaflet and Chart.js vendored** rather than CDN-loaded — smoother map rendering, and the
  viewer shell opens offline. `93ebebf`
- **The map opens on a 60-day window**, with full history on demand. `a5b1340`

Page loads for capture, edit and teams, and the end-of-day flow, were sped up alongside.
`4af1d15`
