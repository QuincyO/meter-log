# 2026-07-25 — Walk-up work counts toward the day

## Mid-day work joins today's route, sized by meters actually installed

`7431cf0`

Sizing Day 1 to the frozen order count over-corrected: it shrank only as its *own* planned
orders finished, so meters installed **off-plan** — walk-ups the worklist never sees —
consumed none of the day's target, and an order added mid-day couldn't join today at all. It
sank to the bottom of the *last* day.

Day 1 is now the target minus every meter installed today, counted over the day cache. Target
20 with 5 planned and 5 walk-ups done shows the next 10 and rolls the rest, no prompt.

Three things here are load-bearing and easy to break: it must run after **every** stop rather
than only a planned one; a day-1 count of `0` is a real value, not "unset"; and the
commit check is keyed on the set's identity, never on capacity.

## The start-location question is a popup, not an inline list

`e73ec60`

Optimize blocks on the answer, so the question belongs *over* the page the way the `confirm()`
it replaced did. Not a native `confirm()` because three answers don't fit one, and an
accidental Cancel has to abort the run rather than silently re-shape the route.
