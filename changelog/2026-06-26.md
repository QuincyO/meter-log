# 2026-06-26 — The app is modularized

## Five phases, one day

`5c8655b` → `bb7231a`

The capture app had grown into a single page carrying everything. It was split into shared ES
modules, in deliberate order:

- **A** — the module split itself.
- **B** — generic offline storage, retention, recent days, offline geocoding.
- **C** — the client computes dispatch downtime; the spine reconciles it at end of day.
- **D** — the map, teams and edit pages migrated onto the same shared modules.
- **E** — `ARCHITECTURE.md` and `CLAUDE.md` updated to describe the modular architecture.

This is the shape the app still has: no build step, no framework, no package manager — just
ES modules loaded directly by the page.

## Dispatch downtime matched at end of day, not live

`c326f53` — ticking "Requested meter?" only sets a flag, so logging a stop stays a cheap
append. The matching happens when the travel review opens.
