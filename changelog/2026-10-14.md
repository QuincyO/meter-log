# 2026-10-14 — Office pages behind a password; GPS off the public site

## The token was never a lock, and the repo was never private

The owner asked for two things. Nobody should be able to open the website and look at
GPS coordinates. And nothing should change the Sheet from the website: the phone adds,
and corrections are made by hand. Looking into that turned up two exposures well beyond
the map page:

- **`SHARED_TOKEN` is public.** It sits in `js/config.js`, which GitHub Pages serves to
  anyone. Hiding a page changes nothing on its own, because anyone can call the Apps
  Script directly with that token. The lock has to be in the spine.
- **The repo was public, and the nightly export lived in it.** `exportSheetToGithub()` has
  committed every tab, every column, to `data/*.md` on `main` since 2026-06-28. That
  includes `Stops.md` (2,939 stops with lat/lng and addresses) and `Employees.md` (home
  addresses). It has run for ~101 nights, and `.nojekyll` served each file raw at
  `quincyo.github.io/meter-log/data/`. AGENTS.md and DEPLOY.md said the exposure was
  "mitigated by keeping the repo private", which had stopped being true.

## What shipped

- **Admin gate in the spine (`Code.gs`).**
  - `ADMIN_GET` covers `pins`, `driveTracks`, `archived`, `tracker`, `timing`,
    `boatdays`, `dispatch`, `downtime`, `nearby`, `avgDispatchTime`, the new
    `adminCheck`, and `day`/`range` with a blank installer (which returned every
    installer's stops).
  - `ADMIN_POST` covers `restoreStop`, `deleteEmployee`, and the team, captain and sub
    saves and deletes.
  - Both sets need `adminKey` to equal the Script Property `ADMIN_KEY`, checked by
    `isAdmin`. It fails closed when the property is unset, and refuses everything for
    10 minutes after 10 bad keys.
- **Login box on the five office pages.** These are map/analytics, edit, teams, reports
  and the planner. `js/admin-auth.js` provides `requireAdmin()`, and each page awaits it
  at top level right after its imports, so nothing binds or loads until the key is
  accepted. The key lives in `localStorage['adminKey']`, and **🔒 Log out** sits
  bottom-left. A key the spine later refuses is cleared and the box comes back.
- **`js/api.js` attaches the key** to every call when one is stored. It adds no new named
  export, because api.js is on the capture page's critical path and per-file shell skew
  turns a new binding into a link error.
- **The export can't publish again.** `githubCommitFiles` throws when `GITHUB_REPO` names
  the app repo (`EXPORT_FORBIDDEN_REPOS`). `data/*.md` is untracked and gitignored. The
  export moves to a private `QuincyO/meter-log-data`, and the repo itself goes private
  on GitHub Pro, which keeps the same Pages URL so phones keep their storage and queue.

## The trap worth remembering

**The other direction fails too.** Putting a capture-side action in an admin set returns
"admin required" to every phone, and the offline queue parks real stops as "stuck".
`tests/admin-gate.test.mjs` scans every capture-side caller (`js/*.js`, `capture.js`,
`tools/wo-bot/bot.mjs`, and the Apple Shortcut's `dispatchRequest`) and fails if any of
their actions is gated. It also runs the real `isAdmin` against stubbed Apps Script
services.

**What is deliberately still open.** The owner chose to keep the phone's Edit, Remove and
Reset buttons. So `updateStop`/`archiveStop`, one *named* installer's
`day`/`range`/`lookup` (GPS included) and `roster` still answer to the public token
alone. Closing them needs per-installer auth on the phone.
