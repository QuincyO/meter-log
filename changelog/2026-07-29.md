# 2026-07-29 — Optimize on the phone needs the district downloaded

## A pack-less Optimize tap no longer routes crow-flies in silence

`js/worklist.js`, `js/pages/capture.js`, `index.html`, `css/capture.css`,
`tests/worklist-optimize-gate.test.mjs`, `ARCHITECTURE.md`, `AGENTS.md`, `USER-GUIDE.md`

Asked for directly: on the worklist screen, **the district has to be downloaded before
anyone can optimize**. The planner is explicitly excluded.

Until now a tap on 🧭 Optimize ran either way — the district pack when the phone had one,
**straight-line distances when it didn't**. That fallback is the problem. It produces a
route that looks solved and is blind to every river, dead end and bridge, and nothing on
screen says which one you got: the same button, the same progress line, the same numbered
pins. A crew can drive a whole day off it without ever learning the map was never
downloaded.

So `optimizeRouteHandler` refuses the tap outright when `installedPacks()` is empty, and
the refusal names the fix — *Download your district first — Settings ▸ Offline road map*.

**The two-second hold is deliberately exempt**, and that is not an oversight to tidy up
later. It skips the pack by design (`opts.noLocalGraph`) and asks a router that has the
turn restrictions the pack does not, so it is the only second opinion a suspect on-device
route has. Gate it too and a crew with a wrong-looking route has nothing to check it
against. It still needs signal, and the offline refusal for a hold on a phone with no
district now points at the download rather than at a tap that would no longer work.

## Saying so before anyone presses it

`paintOptimizeGate` greys the button (`#wlOptimize.gated`), sets `aria-disabled`, and
prints the reason in a new `#wlOptimizeGate` line underneath. Two things are load-bearing
and both are pinned by tests:

- **It must never set `btn.disabled`.** A disabled button fires no pointer events at all,
  which would kill the hold — the one press that legitimately still works — along with the
  tap's own explanatory toast. Greying is CSS opacity plus `aria-disabled`, and the rule
  deliberately carries no `pointer-events:none`. That property on this button belongs to
  the run in flight, which sets it while a route is being worked out.
- **The gate reads `installedPacks()`, never `activePackId()`** — the standing rule from
  2026-07-26, and it bites harder now that the same test decides whether the button works
  at all rather than only what the confirmation sheet says.

**The repaint hole worth remembering:** the ☰ nav lives *outside* `captureMain`, so
Settings opens **over** the worklist screen and closes again without that screen ever
re-rendering. Downloading a district would have left the crew looking at a greyed button
still telling them to download one. `paintRoadPacks()` — the single place both the
download and the delete funnel through — now calls `paintOptimizeGate()`, which is why it
is exported. The delete confirmation stops promising "routes go back to straight-line
estimates" too, because they don't: Optimize stops working on that phone.

The dead branches went with it — the tap can no longer be pack-less, so the
"straight-line algorithm" line in the pre-run sheet is gone and a tap always announces
*offline road map on this phone*.

## Verification

`node --test "tests/*.test.mjs"` — 491/491, with a new
`tests/worklist-optimize-gate.test.mjs` covering the tap gate, the hold's exemption, the
`installedPacks()` source, the paint never touching `disabled`, the CSS not blocking
pointer events, the Settings-side repaint, and `js/pages/planner.js` staying free of
`installedPacks`.

**Driven headless** (`VERIFY.md` §3, Playwright, 390 px, everything off `localhost`
blocked at the browser) against a seeded two-order worklist:

- **No district** — button at `opacity 0.55` with `pointer-events:auto` and
  `disabled === false`, the hint line reading *Download your district in Settings ▸
  Offline road map to optimize*, a tap toasting *Download your district first — Settings ▸
  Offline road map*, no start sheet, and the `order`/`day` columns byte-identical
  afterwards.
- **Hold, no district** — the start sheet opens and says *Google road distances (then
  OpenRouteService, then straight-line)*.
- **District installed, Settings closed over an un-re-rendered worklist** — the button
  repaints to normal (`gated` off, hint hidden) and a tap opens the sheet saying *offline
  road map on this phone*.
- **`planner.html`** loads clean with no page errors and its 🧭 Optimize untouched.
