# 2026-07-24 — Route tuning, real ETAs, and the drive HUD

The biggest single day in the project so far.

## Installer route tuning

`faae202` → `b7796e8`, in four planned parts

1. **A departure constant.** An org-wide `ROUTE_DEPART_TIME` replaced dead per-order
   date/time fields; ETAs anchor to it.
2. **Installer dials.** `commutePull` and `finishBy` persist per installer in
   `WorklistPlans` and weight the per-day home bias. The phone is the source of truth for
   them — a Download pushes the local values up and never overwrites them.
3. **A `#tuning` screen** with a live stops/day readout, so the dials show their effect
   before a route is built.
4. **The crew-start pin and drive-out line**, drawn on both the planner and phone maps.

The crew start is **ETA-only**: it times, prices and draws the morning drive out to the day's
first stop, but it never anchors where the route begins. Only a phone GPS "start from here"
does that.

## Real route ETAs, so the phone fits a workday

`f924e04`

Google Routes and ORS now return real durations, and a run with no road matrix estimates them
from distance. The phone finally shows crew-start ETAs and workday-sized days offline,
labelled "(est.)". Without a travel lookup passed through, ETAs silently collapse to flat
pace — the old "8:15 first stop, no drive-out" bug.

## Drive mode grew instruments

`a4ffc4b` → `4a53d27`

A per-phone driving-stats HUD (distance / average / idle / max, metric, with a moving average
and current-speed readout), a pinned "Driving to" card for the current destination, and a
real-data on-pace projection against two paces — the installer's finish-by target and regular
hours — rendered as an instrument-cluster gauge.

## Four field-reported bugs in one pass

`be30bed`

- **Blank Start/End on the daily-log PDF.** The bookends are read from the request body, but
  on the phone the day row is still empty at preview time, so a call that omitted the typed
  times printed blanks.
- **Drive legs fragmenting.** iOS *kills* a backgrounded PWA during a Maps hand-off, and a
  cold reopen started a brand-new leg each time — a 17-stop day became ~23 fragments, all
  dumped into the queue at Finish. Today's still-open leg is now rejoined instead.
- **A queue that wedged forever** behind one permanently-rejected write. Definitive rejects
  are now retried a bounded number of times, then parked so the rest of the queue drains.
- **GPS speed outliers.** A bad device reading once put `maxSpeed` at 1207 km/h; fixes above
  45 m/s are dropped at ingestion.
