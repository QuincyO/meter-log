# 2026-09-28 — District builder Docker access

## Docker was running, but the helper could not access it

The Districts panel said **Docker Desktop is not running** while Docker was healthy.
The local helper was running as `CodexSandboxOffline`: it could serve HTTP and see
`D:\osrm`, but Docker's config and named pipe were inaccessible. The same Docker
version check succeeded under the desktop user's account. Restarting the helper
outside the sandbox is the runtime repair; restarting Docker is unnecessary.

The helper now reports permission failures explicitly, tells the operator to restart
it under their normal account, and preserves Docker's actual diagnostic for other
failures. A nonzero Docker exit no longer claims that Desktop is closed.

**Trap:** HTTP 200 from `/status` proves only that Node is running. Check `docker:true`
and a populated `pbfBbox`; the bounds require a real osmium container to read the extract.
The launch rule is recorded in the shared repository instructions for every agent.
