# 2026-08-14 — Outage: Google revoked the script's authorization overnight

`DEPLOY.md` (troubleshooting entry; no code changed)

The crew's phones came up with "cannot connect to the server" this morning — a
**fleet-wide production outage of the spine**, live from sometime between
2026-08-13 ~21:15 (last Sheet write) and ~03:00 Toronto (the nightly
`exportSheetToGithub()` trigger produced no commit). Root cause: **Google had
revoked the script's OAuth grant to execute as its owner.** The web app is
`executeAs: USER_DEPLOYING`, so with the grant gone Google refused every `/exec`
request upstream of `doGet` — HTTP 403 with the Drive *"Access Denied — You need
access"* wall — and the same revocation silently killed the 3am export trigger.
No email announced it (no security alert, no Apps Script failure summary).

The fix was one tap: the owner opened the `/exec` URL in a signed-in browser,
got the re-consent screen, and granted; the very next anonymous request returned
`{ok:true, …}`. Total outage ~15 hours, all of it overnight/morning.

What the diagnosis established, in the order it discriminated:

- **The 403 wall sits in front of our code.** Same page with or without the
  token, any user agent — so `SHARED_TOKEN`, `Code.gs` and the phones were never
  suspects. A Google HTML page at `/exec` means Google-level refusal, full stop.
- **`git` was clean by construction**: `Code.gs`/`appsscript.json` last changed
  2026-08-10 and the app demonstrably worked through the 13th, so no deploy did
  this. The Workspace status dashboard showed no incident; the owner's Drive and
  the Sheet itself were healthy (readable via API, last write 21:15).
- **A redeploy does NOT fix a revoked grant — and its success is itself
  evidence.** The CI workflow was dispatched (`workflow_dispatch`, no commit
  needed); `clasp push` + `clasp deploy -i` succeeded and created version 81
  with the manifest's `ANYONE_ANONYMOUS` — and `/exec` still 403'd. That
  eliminated "the deployment's access flipped" and proved the project existed
  and the owner's *clasp* grant (a separate OAuth client) still worked.
- **The discriminator was the owner opening `/exec` in a signed-in browser.**
  JSON → anonymous-only block; the same wall → Drive ACL; a consent screen →
  revoked authorization. It was the consent screen.

Traps worth remembering:

- **The Drive "You need access" wall at `/exec` can mean a revoked grant, not a
  sharing problem.** Nothing in the console shouts about it, no email arrives,
  and the deployment config reads as perfectly correct the whole time — because
  it is. Send the owner to the `/exec` URL in a signed-in browser *first*; it is
  a 10-second test and when the cause is the grant it is also the fix.
- **The nightly export doubles as a dead-man's switch.** A missing
  `Nightly sheet export — <date>` commit on `main` means the spine's triggers
  were dead overnight — that absence bracketed the outage window before any
  console was opened. Worth checking on any morning report of server trouble.
- **The phones' offline-first design carried the field through.** Capture kept
  queueing to IndexedDB; the standing instruction during any spine outage is
  **do not clear site data / reinstall the PWA** — that destroys the unsent
  queue. Everything drained on its own once the grant was restored.
- Why the grant vanished is **unknown** — no password change, no security
  event, no email. If it recurs, check myaccount.google.com ▸ Security ▸
  Third-party access before anything else, and treat a second occurrence as a
  pattern worth a real dead-man's alarm (the export commit is already the
  signal; something should watch for its absence).

## Verification

`curl "<WEB_APP_URL>?action=roster&token=…"` → `HTTP 200`, `{ok:true, employees:[…]}`
(was: 403 + Google's access-wall HTML, reproduced before and after the CI
redeploy, gone immediately after re-granting). Today's missed export backfills
by running `exportSheetToGithub()` once from the editor, or self-heals at the
next 3am trigger — tomorrow morning's commit landing is the confirmation the
trigger survived.
